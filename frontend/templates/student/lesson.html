Architectural Summary: Connection Pooling in High-Concurrency Systems

Directly instantiating a new database connection per incoming HTTP request introduces severe latency penalties (~40ms round-trip TLS and authentication handshake). Furthermore, PostgreSQL forks a backend process per connection, causing RAM exhaustion at scale.

Key Principles Covered:
  • Pool Sizing Formula: connections = ((core_count * 2) + effective_spindle_count)
  • Pool Pre-Ping: Always configure pool_pre_ping=True to catch stale TCP resets before handing connections to route handlers.
  • PgBouncer Transaction Pooling Mode: Essential when deploying stateless container fleets with multi-worker Gunicorn servers.

Flask SQLAlchemy Engine Configuration Example

from sqlalchemy import create_engine
from sqlalchemy.orm import scoped_session, sessionmaker

engine = create_engine(
    "postgresql+psycopg2://app_user:secret@pgbouncer:6432/orders_db",
    pool_size=10,
    max_overflow=20,
    pool_timeout=30,
    pool_recycle=1800,
    pool_pre_ping=True
)

db_session = scoped_session(sessionmaker(autocommit=False, autoflush=False, bind=engine))
