Distributed Token Bucket Rate Limiter with Sliding Window

Problem Description Difficulty: Medium

Challenge Overview

Implement an idempotent rate limiting function is_request_allowed(client_id, max_tokens, refill_rate_per_sec, current_time) that maintains a sliding window bucket per client.

Constraints

  • Time complexity: O(1) per request
  • Space complexity: O(N) where N is unique active clients
  • Tokens must accurately refill based on microsecond elapsed differences

Example 1:

client_id = "user_891"
max_tokens = 5
refill_rate = 1.0  # 1 token/sec

# 1st request at t=0.0 -> Allowed (4 remaining)
# 2nd request at t=0.1 -> Allowed (3 remaining)
# 3rd request at t=0.2 -> Allowed (2 remaining)
